# Gravity Golf

A puzzle golf game on tiny solar systems, built in **Unreal Engine 5.9** (preview) by Claude Code alone.
`docs/VISION.md` is the design and business plan. `legacy/` holds the 2022 web version for reference (gitignored).

## Principles

- **Code-first.** Everything that can be text is text. Gameplay is C++, holes are JSON, materials are generated by
  Python. Never hand-edit a `.uasset` you could regenerate; change the script and re-run it.
- **Deterministic simulation.** `Source/GravityGolf/*/Sim/GGSim.*` is plain C++ (no Unreal types). It uses only
  `+ − × ÷ √` on doubles, with FP contraction off, so shots replay bit-identically everywhere. Derived trig values
  are quantized in the loader. Keep it that way: no `sin`/`cos`/`atan2` inside the step.
- **Latest and experimental.** Prefer the newest engine features. Research current releases rather than relying on
  memory.

## Puzzle law (Ken's rule)

This is a puzzle game. The player must think. Every hole is designed so its components are **necessary**:

1. **Impossible without the tools.** With no machine placed, no swing sinks the ball. Banks, lucky bounces and
   brute force must all fail.
2. **Solvable by an idea.** With the tools placed well, a comfortable range of swings sinks it. The hard part is
   working out *where things go and why*, never pixel-perfect aim.
3. **Proven, not assumed.** `Tests/Sim/solve.sh <course>` brute-forces both claims with the real physics. A hole
   doesn't ship until it prints PASS. Re-run it after any change to the course or the physics.
4. **One swing per leg.** If the ball stops anywhere but the cup or a safe zone, it returns to the last safe spot.
   (Free multiple strokes would let players walk the ball around every obstacle.)
   **Safe zones** are optional, per level: pads where a resting ball stays, making long holes a chain of legs.
   The solver proves every leg separately.
5. **The club is a putter.** The ball rolls. Height, curves and anything else come from the machines.
6. **One new idea per hole**, taught by the level itself.

## Critique everything (Ken's rule)

Claude is the only developer, so nobody else will catch a weak decision. After every meaningful step, critique it
before moving on, and say the critique out loud in the report to Ken:

- **Decisions:** what was chosen, what the alternatives were, and what would make this choice wrong.
- **The game:** is this fun, clear and new? Would a player understand it without help? Is the puzzle an idea or
  just an aim? Compare honestly against The Talos Principle and Golf With Your Friends.
- **The look:** judge every screenshot as a harsh art director would. Name what's ugly, flat, fake or boring, and
  fix the worst thing first. "Better than before" is not the bar; the reference games are.
- **Functionality:** play it (PIE), don't assume. List what was verified in-engine and what wasn't.
- **Process:** note mistakes in how the work was done (for example, launching two editors) and fix the cause.

Never report something as good when it is merely working.

## Layout

```
GravityGolf.uproject          plugins: ModelContextProtocol + AllToolsets (MCP), Python, ProceduralMesh
Source/GravityGolf/
  */Sim/GGSim.*               deterministic 3D ball physics (boxes, surfaces, attractors, cup)
  */Game/GGCourse.*           loads Content/Courses/<level>.json, steps the sim at 240 Hz, ball/attractors/flag
  */Game/GGGolfer.*           first-person character: walk, carry attractors (E), swing (hold click), loft (scroll)
  */Game/GGGameMode.*         starts the course matching the level name; automation flags (-GGView, -GGShot, -GGCapture)
  */Game/GGAudio.*            runtime-synthesized sounds (footsteps, strike, bounce, cup, machine)
  */Game/GGHUD.*              placeholder HUD
Content/Courses/*.json        collision boxes + rules, written by Tools/courses/<level>.py (plain Python)
Tools/levels/<level>.py       builds the level in the editor from the course JSON plus dressing (common.py helpers)
Tools/build_materials.py      generates /Game/Materials (custom HLSL: triplanar scans, ocean, ball, glow)
Tools/fab_assets.json         Fab/Megascans packs the levels need. They are gitignored; reinstall via the Fab toolset
Tools/editor.sh               start the editor and wait until its MCP server is idle
Tools/mcp.py                  shell client for the editor's MCP server
Tests/Sim/run.sh              standalone sim tests
Tests/Sim/solve.sh <course>   puzzle-law proof: impossible without the machine, solvable with it (about 1 min)
```

## Commands

```bash
UE="/Users/Shared/Epic Games/UE_5.9"
Tests/Sim/run.sh                                             # sim tests, no Unreal needed
python3 Tools/courses/terraces.py                            # regenerate a course JSON
"$UE/Engine/Build/BatchFiles/Mac/Build.sh" GravityGolfEditor Mac Development -project="$PWD/GravityGolf.uproject"
Tools/editor.sh                                              # start the editor, wait for MCP
```

Work through the Unreal MCP (`mcp__unreal__*`) while the editor is open:

- Run repo scripts with `editor_toolset.toolsets.python_scripting.PythonScriptingTools.execute_python` and
  `runpy.run_path('<abs path>', run_name='__main__')`. Long scripts can time out on the client yet still finish;
  check the log.
- C++ changes that touch class layouts need the editor closed: `EditorAppToolset.ExitEditor`, Build.sh, then
  `Tools/editor.sh`.
- Play and look: `EditorAppToolset.StartPIE` (warmupSeconds 10+), `SceneCaptureToolset.CaptureGameViewport` with
  the PIE world from `ListWorlds`, then `StopPIE`.
- Read the log with `ConsoleToolset.LogsToolset.GetLogEntries`.
- Replay a solver result in PIE with console commands (`ConsoleToolset.RunConsoleCommand`): `GGMachine x y z`,
  then `GGShot yaw power`, and read `LogGGCourse` for the outcome.
- Fab installs: `FabToolset.InstallFabListing`, then save dirty packages.

## Gotchas

- Run exactly one editor. Start it only with `Tools/editor.sh`, never in the background alongside another call.
  A second editor can't bind the MCP port and silently runs without it.

- A standalone `-game` launch (Tools/capture.sh) hung at startup compiling global shaders after ray tracing was
  enabled. Use PIE captures until that's understood.
- The first editor start after changing renderer settings recompiles shaders and rebuilds Nanite data for the
  Megaplants trees (several minutes). MCP tools return "slow task" until it finishes.
- Megaplants need `r.Nanite.Foliage` and `r.Nanite.AllowAssemblies`, or the trees render bare.
- Post-process exposure min/max brightness are luminance values, not EV; setting them high makes the game look
  like night.
- macOS 27 with Xcode 27.2 works (UE 5.9 allows up to 27.9). The Metal toolchain must be installed
  (`xcodebuild -downloadComponent MetalToolchain`).
